# M1 受控读发测试计划（未执行）

此文档是后续验证方案，不构成连接真实微信或发送消息的授权。M0 仍只有 mock；不得通过 `--mode mock` 对接真实客户端，也不得把模拟核验当作客户端证据。

## 进入条件

1. 用户明确允许一个具体账号、一个专用测试会话、测试时间窗口和只读检查范围。发送需另有明确授权，并确认固定短文本和最多一次尝试。
2. 先在合成测试中完成候选适配器的目标识别、草稿保护、有界超时、暂停和核验接口；独立评估库的准确版本、许可证、依赖和 import 副作用。
3. 读取实际运行客户端版本，不根据安装登记推断；记录 OS 构建、Python、适配器提交/版本及显示缩放。没有实测证据的字段填“未提供/未验证”。
4. 确认不会覆盖已有草稿或剪贴板；设计可触达的紧急停止，并验证底层自动化 fail-safe 没有被关闭。

## 顺序与验收

| 步骤 | 受控操作 | 验收与停止条件 |
| --- | --- | --- |
| 1. 只读定位 | 仅定位获准账号及测试会话，检查必要 UI 可访问性 | 账号/会话不唯一、掉线、锁屏或 UI 无法识别立即停止，不浏览其他会话 |
| 2. 只读读取 | 从专用会话读取事先约定的合成测试文本 | 记录匹配方式，重复事件去重；自己发言不触发回复，不导出全量 UI/联系人 |
| 3. 预演 | 校验白名单、固定短文本、人工确认、连接、草稿与当前目标 | 全部通过才能进入发送；有草稿必须保留并停止，不自动清空 |
| 4. 一次尝试 | 获准后先持久化请求 ID，再紧邻动作检查目标，最多触发一次 | 明确区分未尝试、已尝试和已知失败；禁止自动重试 |
| 5. 回读核验 | 在同一测试会话核对己方消息与固定短文本 | 匹配仅记 `ui_confirmed`；发送后超时、掉线、目标改变或证据不唯一记 `unknown` |
| 6. 重启/暂停 | 仅检查状态恢复与停发，不再次发送 | 相同请求不会重放；暂停期间没有新动作；不通过新请求 ID 绕过不明结果 |

故障矩阵先用 mock 运行，再在明确获准、不会产生额外发送的条件下验证真实边界：目标不匹配、身份不确定、已有草稿、只读/预演、重复事件、自己发言、断线、动作前超时、动作后超时、核验缺失、暂停和进程重启。
