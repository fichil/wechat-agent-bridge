# Windows 便携包使用说明

下载 Release 中的 WeChatAgentBridge-版本-windows-x64.zip，核对同页 SHA-256，完整解压到可写目录，例如 C:\Apps\WeChatAgentBridge。不要在 ZIP 内直接运行，也不要仅复制 EXE。

目标：Windows 10 1809/11 x64、Windows Server 2019/2022/2025 桌面环境。主要验收目标是 Server 2025、2 核、4 GiB。无需安装 Python、Node.js、MSVC 或额外 .NET。微信需单独安装并在同一 Windows 用户桌面会话登录。保留 4.1.15.56 精确构建支持；4.2.0.9 的阶段验证状态见兼容档案和账号页面，同版本号仍须通过指纹检查。读取与发送分别进行自动检查，就绪后恢复已开启的会话。

## 首次启动

个人使用时，在服务器远程桌面打开启动器，勾选“私人访问（SSH）”，不用填写域名。填写管理员用户名和两次密码后保存、启动。服务器本机在 `http://127.0.0.1:18765` 登录；另一台电脑解压同一 ZIP 后双击“连接私人后台.cmd”，输入 SSH 地址和用户名。也可运行下面命令，再在本机浏览器打开同一地址：

    ssh -N -T -o ExitOnForwardFailure=yes -L 127.0.0.1:18765:127.0.0.1:18765 Administrator@你的服务器IP

SSH 窗口需保持打开；关闭只断开访问，不停止服务器后台。私人模式的网页端口 18765 与 API 端口 8765 都只绑定 127.0.0.1，不需要放行这两个公网端口，不依赖 DNS、80/443 或公网证书。两台机器之间的传输由 SSH 加密；浏览器到本机隧道端口使用回环 HTTP，登录仍要求密码、HttpOnly/SameSite Cookie、来源和 CSRF 校验。主机指纹需按 SSH 提示核实；程序不会关闭主机身份验证。

服务必须从已登录的远程桌面启动。不要通过 SSH 命令启动常驻后台：Windows OpenSSH 可能在该连接关闭时回收其子进程。SSH 隧道只连接已经运行的后台。

需要公网域名 HTTPS 时，取消勾选私人访问，再按以下步骤配置：

1. 将一个子域名的 DNS A 记录指向服务器公网 IP，例如 Host 填 bridge，获得 bridge.example.com。保留其他网站记录。云平台及 Windows 防火墙放行 TCP 80/443；后台 8765 不对公网开放。
2. 双击 WeChatAgentBridge.exe。填写域名、管理员用户名和两次密码（4–128 字符），点击“保存首次配置”。没有默认密码。已有管理员时修改域名应留空密码；忘记密码使用“重置密码”。
3. 点击“环境检查”及“启动后台”。Caddy 自动申请和续期证书。成功启动不等于证书已签发；刷新状态查看结果，再用另一台电脑或手机验证 HTTPS 地址。若域名所在服务要求备案或网络准入，需按服务商要求完成。
4. 点击“打开后台”登录，配置角色卡、API 和会话。打开或关闭网页、关闭启动器窗口不会停止后台；“停止后台”才会正常结束服务。

中国大陆服务器公开提供网站服务时须按云服务商要求完成备案；改用 IP 不是备案豁免。私人模式用于经 SSH 认证的个人管理入口，不把后台作为公网网站开放。

运行数据全部保存在包目录下 data，包括 bridge.sqlite3、auth.sqlite3、production 日志、Caddy 证书、发送回执和本机验收记录。不要将 data 放入网页目录或上传公开仓库。

## 自动回复就绪检查

首次启动、程序升级、微信进程变化和数据迁移后，后台自动核对微信精确构建、文件与内存代码、发送组件、账号唯一绑定和同步状态。检查通过后，已开启且配置就绪的会话自动恢复；不需要人工发送验收或点击恢复，不会为检查额外发送消息。

未知构建、身份冲突、损坏组件、不可读的 API 密钥会显示具体原因，条件恢复后自动重查。会话关闭和用户暂停保持原样；已经提交但结果不确定的发送不会自动重试。

历史 native-send-acceptance.json 仅作为旧版本记录保存，不再控制新版本发送资格。自动检查不代表已经执行窗口、草稿和剪贴板等真实发送观察。

## 私人数据迁移

迁移包含本项目已归档聊天、缓存媒体、角色卡、记忆、设置、API 配置及管理员密码哈希；不包含微信客户端聊天目录和登录状态。

源便携程序点击“导出全部数据”，会停止后台并保持停止。源码版先用原启动入口正常停止，再运行：

    python -m bridge_portable.migrate export --data 原项目\.local --file 私人迁移.zip

不要在运行中只复制 SQLite 主文件。迁移 ZIP 包含私人聊天与认证资料，只私下传输，不能作为 GitHub Release 附件。

目标机器点击“导入迁移包”，选择私人 ZIP。程序验证校验值、版本和数据库完整性，已有数据先备份到 data/migration-backups，失败回退。导入会撤销旧网页会话，管理员密码保持不变。

完整迁移包支持 v8–v12，低于 v10 的旧数据在暂存库升级到 v10，首次启动继续升级至当前 v12。跨机器或 Windows 用户后，旧 API 密钥和 SMTP 授权码通常无法解密，需重新输入并测试。角色卡、角色卡派生关系、记忆、会话开关和重试次数保留；账号自动检查期间暂缓处理。旧队列不会重放，结果不确定的发送仍需人工核对。导入后邮件通知默认关闭，保存 SMTP 配置并测试成功后再启用。仅导出角色/API 时，派生角色卡作为普通角色卡导入，不携带原账号或会话归属。

启动后台，重新登录微信，等待账号与同步基线就绪，填写不可读的 API 密钥。确认源电脑保持停止；目标账号就绪后自动恢复，仅新水位之后的实时触发可以发送。

## 升级、备份与排错

从 **v0.4.0** 开始，网页顶栏“版本更新”和启动器“检查版本更新”显示同一状态。启动后及每 24 小时检查公开 GitHub 正式 Release，不需要 GitHub 登录。只有点击“一键升级”并确认目标版本后才会下载；也可以稍后再处理。网络中断、限流或附件不齐全时可重新检查。

首次迁入：从 GitHub 下载完整 ZIP，解压到新的可写目录。正常停止原后台，另存一份完整的旧 `data` 备份，然后把整个 `data` 复制到新解压目录，打开根目录的 `WeChatAgentBridge.exe`。旧版无法自行发现此版本。要在相同 Windows 用户下继续使用原管理员、聊天、API 密钥和发送记录，不要清空数据或重新初始化，也不要同时运行两份后台。

以后始终打开根目录的启动器。程序在本地维护并存版本、独立更新运行时和备份，数据保留在根目录的 `data`。切换前会等待在途任务结束并验证冷备份；失败时回退兼容程序，保留最新数据。升级中请保持用户登录。断电后重新打开根启动器，会恢复未完成的更新；原本停止的后台升级后保持停止。

发布者：在 Actions → **Prepare GitHub Release** 输入正式版本号及中文更新说明。默认完成测试、打包、升级演练并生成含 ZIP、SHA-256、清单的草稿；点击 Publish release 后客户才会发现。也可勾选直接发布并设为最新正式版。已存在的版本号不会被覆盖。服务器的 main 自动部署是独立流程。

只迁移角色卡和 API：在源程序点击“仅导出角色/API”，目标使用“导入迁移包”。此包只带完整角色卡、API 地址/协议/模型等配置及默认选择，不包含密钥、聊天、媒体、旧账号、记忆、会话设置、管理员或登录状态。导入不覆盖目标现有配置；编号冲突会拒绝，并在替换失败时回退。API 密钥必须重新填写并测试。源码导出命令为 `python -m bridge_portable.migrate export-config --data 原项目\.local --file 角色和API.zip`。

微信进程或构建改变会持久暂停自动处理。在后台“微信版本兼容”查看各项能力和等待原因。识别唯一账号、同步完成、组件及会话配置可用后自动恢复；身份变化前的旧队列不会补发，原来的用户暂停仍生效。未知指纹不按版本前缀放行。

升级前停止后台，将整个 data 目录备份，再将 data 复制到新版本解压目录，保留旧程序与数据快照。不要用程序包覆盖 data。相同机器升级会自动重新检查；微信身份未变时保留待处理队列。v9→v10 和角色卡演进的 v11→v12 均须先安装兼容桥接版本，回退只允许使用支持当前数据版本的程序并保留最新数据，具体见自动部署说明。

端口冲突时不抢占其他进程。“查看日志”打开 data/production。停止会等待在途模型请求正常收尾，最长可超过半小时，窗口保持响应；不要用任务管理器强行终止正在发送的进程。

程序运行在微信用户的桌面会话，不是系统服务。远程桌面可以断开，不能注销用户。重启后需登录用户、运行微信并重新启动程序。SSH 适用于上传与维护，不能代替微信桌面登录。

## 可复现构建

构建机需要 Python 3.12、Node.js 和 MSVC x64 Build Tools。先执行 scripts/build_runtime.ps1；它验证固定源码和 VC 运行库来源的校验值，编译 Python 3.12.16 并创建私有运行时。

从 Caddy 官方 v2.11.7 Release 下载 caddy_2.11.7_windows_amd64.zip。scripts/build_portable.py 验证固定 SHA-512。npm ci 后，在干净、固定提交的工作树执行：

    python scripts/build_portable.py --version 0.3.0-rc.1 --commit HEAD --runtime .local/build-cache/runtime-3.12.16 --caddy-zip .local/build-cache/caddy_2.11.7_windows_amd64.zip

源码白名单排除个人数据、运行目录、测试夹具及开发依赖。版本清单记录提交、依赖版本和文件 SHA-256。development 构建仅用于本地测试，不能作为正式 Release。
