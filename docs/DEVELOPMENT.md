# 本地 Codex 开发交接

## 当前状态

这是一个新项目的文档起点，尚未实现收发、模型连接、人设记忆或账号管理。不要把调研项目的能力当成本仓库的能力。

目标是建立可替换模型、可替换微信适配器的智能体系统。具体 AI 角色是配置或示例，不应硬编码进框架。

## 建议架构

- Adapter：封装客户端读取、目标定位、发送与结果核验。
- Domain：规范化 MessageEvent、ActionRequest、ActionResult。
- Policy：校验允许的账号/会话、操作类型、速率与人工确认。
- Provider：模型调用接口。先用 mock，后续再添加提供方实现。
- Agent：根据人设、相关上下文与记忆提出回复或选择沉默。
- Memory：按账号和会话隔离，支持保留期限与删除。
- Application：启动配置、预演、暂停及可脱敏诊断。

这是设计建议，不是现成目录或已实现接口。

## 里程碑

### M0：离线接口与测试
1. 设计消息事件及操作结果的数据结构。
2. 实现 mock adapter、只读/预演策略与基本去重。
3. 用合成数据验证目标不匹配、重复消息、自己发言、超时和 unknown 结果。
4. 所有测试无需微信、账号或 API key 即可运行。

### M1：受控读发验证
1. 只读确认实际客户端版本，不依据过期安装登记推断。
2. 对专用测试会话检查 UI 可访问性；不批量导出 UI 文本或遍历聊天。
3. 只有在范围明确获准后，发送一条固定短文本并回读。
4. 已有草稿不覆盖，账号/目标不确定则停发。
5. 若已触发发送但确认超时，结果为 unknown，不能自动重发。
6. 记录具体测试环境与失败边界；不承诺泛化到所有客户端。
7. 不开启全会话监听、自动回复、好友管理或模型上传。

### M2：多模型接入
定义稳定 Provider 接口，用至少两个 mock/provider 实现证明模型可替换；真实 API 密钥由部署者安全配置，避免硬编码。添加 token/费用限制及超时控制。

### M3：人设与记忆
实现必要上下文拼装和会话隔离；明确数据存储、删除及第三方传输行为。模型返回回复候选或不回复，执行层仍独立做权限校验。

### M4：受控自主行为
指定会话内先做被动回复，再探索主动搭话。增加人工接管、冷却、频率限制、防循环和异常停发。

### M5：账号工具扩展
好友申请、联系人管理等作为独立能力评估。不要因为已有消息发送权限而自动获得删除好友或邀请权限。

## 上游复用注意

可调研 pywechat/pyweixin、wxauto；采用前检查固定版本而非只看 README。
- 核查许可证及包元数据是否一致；不要把参考项目的代码直接改名发布。
- 核查 import 是否操作客户端、修改全局 fail-safe。
- 核查发送是否清除草稿、覆盖剪贴板、把长文本转换为文件或隐式发送。
- 核查读取是否导航其他窗口或关闭客户端。
- 核查是否支持本机具体微信版本及 UI 可访问性。
- 不将收费功能描述为免费版能力。
- 不以降级客户端、绕过登录或禁用安全保护作为默认解决办法。

## 第一项交给 Codex 的任务

先完成 M0：建立最小项目骨架、mock adapter、消息/操作结果模型、策略校验与单元测试。输出实现说明与 M1 测试计划。未经明确授权，不连接真实微信、不发送消息、不安装整套第三方自动回复项目、不调用真实模型 API。

当前没有确定编程语言或依赖锁文件；Python 是初期 Windows 自动化的候选，不是强制要求。请根据接口与依赖评估给出最小方案。
