# M1 实现说明

## 交付范围

本地控制台和 mock 端到端链路可运行。兼容 API 使用真实 HTTP 实现，并以本机合成服务器验证协议。Windows 续测已在授权下临时开放控件并核验账号/当前群，但 SetValue 使微信跳到前台，后台写入已禁用；真实读发没有启用，**不能作为已完成 M1 使用**。证据及新增受限诊断入口见 [后台验收](M1_BACKGROUND_ACCEPTANCE.md)。

## 启动与保存

`python -X utf8 -m wechat_agent_bridge console` 默认 Mock。可选 `--adapter windows`、`--port 8765`、`--data-dir .local/console`、`--no-browser`。只能绑定 `127.0.0.1`，不提供绑定公网选项。无前端构建步骤。

浏览器启动地址的 fragment 带随机本机会话凭据，页面加载后移除；服务器使用 HttpOnly/SameSite=Strict Cookie 和独立 CSRF token。Host 必须匹配端口，写请求还需精确 Origin。禁止缓存和嵌入页面，内容以 DOM `textContent` 渲染，不信任聊天中的 HTML。启动地址也应只供本机使用。

DPAPI 使用当前 Windows 用户范围；启动先检测加解密，无明文 fallback。SQLite 的内容字段与附件均加密。搜索键、消息去重、发送指纹为哈希；时间、状态、调用数量是操作元数据。加密不能阻止已经控制当前 Windows 用户进程的程序访问数据。

mock/windows 分别使用 `mock-state.sqlite3` 和 `windows-state.sqlite3`，独立于 M0。配置、授权、消息和摘要保留到手动删除；重启全局与账号均暂停。关闭网页不停止后台；全部暂停可阻止后续上传/发送，终端 Ctrl+C 结束服务。已经提交给外部服务的请求不能撤回，其过期结果会丢弃。

## 数据流和调度

1. 账号发现不读取聊天内容；身份未核验不能保存读取授权。窗口进程与账号分别标识。
2. 获准账号枚举会话，排除项不进入消息读取。初次最多读取当前可访问的 50 条；历史回填只保存，不触发回复。
3. 消息存储保留双方内容、附件、时间和身份信息；页面标注同步时间、覆盖范围、未知 ID/未读状态。
4. 每 5 秒尝试同步已授权且未暂停的账号；新私聊或明确群 @ 入持久任务队列。默认 3 秒合并，同会话按序，桌面操作全局串行。
5. AI 输入为系统提示词、该会话旧摘要、最近记录/触发消息和附件解析。最近消息优先；输入预算约 16,000 字，单条正文最多 2,000 字，截断明确标记。模型只返回 `{"reply": "文本"}` 或 `{"reply": null}`。
6. 回复前重新校验授权、暂停、账号、会话、草稿和连接；先保存执行日志，再调用适配器。保存 attempted/ui_confirmed/failed/unknown，unknown 隔离该会话后续发送。人工核对入口仅解除隔离并暂停，不重发原任务。
7. 每 180 秒只处理有新内容的会话摘要；成功保存后推进来源水位。无新增记录不调用模型、不发送微信。

默认上限 120 次/滚动小时、1,000 次/滚动 24 小时，失败调用和能力测试也计数；不是账单/token 精确计量。回复上限可在 1–500 字调整，发送间隔可在 1–3,600 秒调整（默认 10）。附件上限目前是代码常量：20 MB、30 秒。

附件可用时提供图片预览、音频播放、下载及解析内容；只有启用上传后生成 AI 理解结果。语音当前实现兼容转写接口，真实客户端自带转写的读取仍待适配。文档仅提取数据：PDF 无 OCR，DOCX 文本/表格，XLSX 缓存值而非公式求值。复杂/超限/加密/无文本文件失败时说明原因，不能推测内容。

## HTTP 接口

除静态资源及握手外均需要会话认证。POST 还需要 Origin 和 `X-CSRF-Token`；接口不接受任意本机文件路径。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST / GET | `/api/session` | fragment 凭据换 Cookie / 已登录页面获取 CSRF |
| POST | `/api/discover`、`/api/probe-account` | 发现候选窗口/账号；显式选择窗口核验自己资料 |
| GET / POST | `/api/config` | 密钥脱敏读取 / 保存配置并暂停 |
| POST | `/api/provider-test` | 固定合成内容的 text/vision/transcription 测试 |
| POST | `/api/grant` | 三项账号权限、账号暂停、排除项；上传绑定服务地址 |
| POST | `/api/conversations`、`/api/sync` | 枚举获准账号会话 / 当前或更早可访问记录 |
| GET | `/api/messages`、`/api/attachment` | 按 account/conversation 查询消息分页或已登记附件 |
| GET | `/api/memory`、`/api/status` | 摘要、水位、调用量、任务及异常状态 |
| POST | `/api/pause`、`/api/resume` | 全局暂停 / 重新建立基线后处理新增内容 |
| POST | `/api/clear-memory` | 删除账号或会话消息、摘要、附件、派生解析和任务 |
| POST | `/api/acknowledge-unknown` | 人工核对后解除当前会话隔离，必须 `reviewed: true` |
| POST | `/api/mock-inject` | 仅 Mock 模式注入新合成消息 |

## 已知限制及尚未实现

- **真实微信**：空 UIA 树无法核验账号/会话/输入框。无已验证的读取或发送 profile。候选文本定位代码没有真实运行证据，不能启用作为受支持适配器。
- **身份及版本**：已验证运行文件版本发现；安装登记值记录于验收文档，控制台尚未整合安装登记面板。真实账号去重、稳定跨重启会话 ID、发送者/己方/群 @ 和附件获取都待验证。不会用昵称推断。
- **发送**：真实 Windows 发送路径主动禁止执行；没有把未经验证的 UI 键盘操作接上自动回复。mock 的 ui_confirmed 仅证明策略链路。
- **AI**：官方 OpenAI 已有一次独立合成文本/JSON 校验成功记录，见 [OpenAI 测试记录](OPENAI_TEST.md)。真实聊天、摘要质量、图片、语音及不同兼容方参数差异未实测；仅支持本轮实现的两个接口协议。静音转写样本仅检查受理，非 JSON 回复拒绝发送。
- **历史**：mock 有本地分页，Windows 没有可验证的历史翻页/完整性和连续消息捕获能力。`seq` 是本地入库顺序，后加载的历史在摘要中按入库顺序处理，并保留原时间；不是全量历史或严格时间排序的长期检索系统。
- **调度**：单工作队列先保串行性，慢模型会延迟其他会话。无后台系统服务、自启动或生产级长时间稳定性声明。
- **删除**：数据库删除内容并启用 SQLite secure_delete；最小 seen/actions/cooldown/unknown 隔离记录保留。不能保证操作系统备份/外部复制副本的物理擦除。已删除旧消息不会重新入库，避免重新触发。

后续必须补齐并真实验收这些能力，才能按计划将 M1 标为完成。
