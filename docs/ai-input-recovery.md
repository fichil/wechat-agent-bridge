# AI 输入超限与定向恢复

文本输入预算为 256 KiB，按 UTF-8 字节统计实际系统提示词和移除图片二进制后的消息 JSON；输出文本校验仍为 64 KiB，请求体上限仍为 20 MiB。程序不会为了通过检查截断角色卡、记忆或消息，也不会额外调用模型压缩记忆。

批次过大时仅减少本次纳入的消息，并同步重算回复目标、触发消息、最终批次及改卡权限；剩余消息后续处理。固定资料或单条消息仍超限时，工作台显示实际大小、上限及各部分占用，并说明尚未调用模型。已保存的重试快照保持原样。

## 群聊恢复命令

只恢复最新任务确为 `ai_input_too_large`、仍开启 AI 且处于暂停状态的指定群聊；拒绝在途或挂起任务、未解决的发送记录以及配置缺失。默认预览使用只读连接，不初始化 Store、不迁移数据库、不启动同步或模型请求。

在当前程序目录运行，所有标识从该会话失败任务读取：

```powershell
python -B -X utf8 -m backend.app.ai_input_recovery --database <数据目录/bridge.sqlite3> --account-id <账号ID> --conversation-id <会话ID> --expected-run-id <最新失败任务ID>
```

确认预览后，在后端正常停止的维护窗口执行同一命令并加 `--apply`。程序取得维护锁及后端数据库所有者锁，创建并校验 `maintenance-backups/ai-input-*.sqlite3` 备份，然后在一个事务中执行恢复。相同失败任务重复执行返回 `already_applied`，不重复建批次或更新回复起始时间。

恢复会建立固定的历史记忆批次，旧积压不回复、不改角色卡；现存旧触发资格失效，回复起始时间和同步水位重新建立。恢复时刻之前才补入的旧消息不能重新触发回复。新消息按原配置处理，新的群聊 @ 仍优先于后台补记忆。暂缺图片、语音转写或不支持的消息保留原状态，后续具备条件时按正常记忆处理流程纳入。

恢复不改写原失败任务、会话配置、角色卡或已保存记忆，不修改已有发送记录，也不恢复其他会话。恢复凭据保存在数据库 `metadata`，只含目标标识、数量、记忆摘要哈希、时间边界、批次和备份位置，不含聊天正文或密钥。

正常启动后检查新批次为 `memory_backfill`、发送状态为 `not_required`，以及待处理数量是否下降。等待自然新消息验证后续回复；没有自然消息时，只能确认历史恢复和服务状态，不能宣称真实回复验收完成。回退程序时保留最新数据库，禁止用恢复前备份覆盖已产生的新消息和发送结果。
