# 群聊合批与 token 节省

## 行为

普通群聊按原有条数门槛冻结一批实时、未消费消息。100 条正常文本只生成一次请求；第 101 条等待下一轮。@ 提前携带当前待处理新消息，例如 59 条加 1 条 @ 一次处理 60 条。成功时，记忆、消息消费和发送队列仍在同一事务提交。只有输入预算超限才拆批，失败或未纳入的消息不被消费。

图片、表情以占位描述参与计数，不再按每 4 张截断消息。最多选择 4 张原图：引用指向、@ 附图、提问者前 3 条邻近图片。占位完成后图片缓存变化不触发自动补录。引用已处理媒体作为上下文，不重复计数。语音仍等待转写；原始档案不被删除。

群聊工作记忆目标 3000 字符、上限 4000。压缩调用只有原记忆和摘要协议，不携带角色卡、图片或发送权限。旧记忆在 metadata 备份，压缩开始和结果写入任务；一次前置压缩、一次超限结果压缩各自最多执行一次，未知结果不会因重启重发。压缩失败保留原数据并暂停；手工修改仍由修订号保护。明确输出容量错误最多切换一次备用配置，不反复调用同一配置。私聊合批规则和其他群的门槛未更改。

日志追加可选的 `input_tokens`、`output_tokens`、`cached_tokens`、`total_tokens`、`image_count`、`placeholder_count`、`http_attempt_count` 和 `split_reason`。无 usage 为未知；实际调用次数包含压缩调用。提示词仅出现在系统消息，不重复嵌入用户 JSON。SQLite schema 仍为 v12，扩展状态使用既有 JSON payload/metadata，不改变角色卡协议。

## 验证

- 合成测试覆盖 99/100/101 条、59 条加 @、大量图片占位、引用旧图片、缓存补齐、请求期间新增、重启、重试、输入预算拆批和配置冲突。
- 记忆测试覆盖前置备份、超限压缩、失败不消费、重启不重发、并发手工修改及容量错误最多一次备用。
- 保留发送去重、未知发送阻挡和角色卡演进的回归；旧的固定 50 条拆批测试改用真正的输入字节超限，继续验证暂停/恢复。
- 前端日志验证未知 token 和本批条数显示；后端 OpenAPI 与生成的前端类型同步。
- 最终测试、CI 和生产运行结果以对应发布记录为准，不把合成用例当作自然群聊的计费结果。

## 上线与维护

使用既有 main 测试、构建和部署流水线；关闭的群保持关闭，已取消的轮次不恢复。切换前后检查版本、健康接口、群开关、门槛、发送计数及取消轮次。

仅对明确指定且已关闭、没有活动任务的群执行一次维护：

```powershell
python -B -X utf8 -m backend.compact_group_memory --database <data/bridge.sqlite3> --account-id <account_id> --conversation-id <conversation_id>
```

该命令不启动 Store、同步器或微信发送器。使用已验证的当前 API，先备份并保留请求标记，调用一次摘要，再以原配置/记忆修订号和关闭状态进行条件提交，并将该群额外重试设为 2。重复运行同一记忆修订被拒绝；失败或结果不确定时必须先核对记录。输出仅包含结果、字符数和备份键，诊断日志在本机保存。

程序回退保留当前数据库和聊天；不要用升级前数据库覆盖新记录。原记忆可从本机 metadata 的维护备份读取，只有核对修订和会话关闭状态后才手工恢复。token 改善通过每百条消息实际 usage、失败 usage、请求数和记忆字符数比较；不承诺固定节省比例。
