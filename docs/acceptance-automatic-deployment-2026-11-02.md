实现见 [PR #3](https://github.com/fichil/wechat-agent-bridge/pull/3)，部署与本机维护命令见 [自动部署说明](automatic-deployment.md)。

## 首次发布

- 首次成功的 GitHub 完整发布：[Actions 41377173790](https://github.com/fichil/wechat-agent-bridge/actions/runs/41377173790)，提交 `a851f021ccfd49e29aa3d8384f13111e660c5136`。
- 262 项后端、54 项只读读取器、35 项前端单元测试、36 项浏览器回归，以及接口契约、HTTPS 和便携运行时验证通过。
- 服务器验证上传包、提交和文件哈希，正常停止旧后台，创建并校验冷备份，然后先暂停业务启动候选版本。登录页、健康接口、数据库和匿名访问边界通过后自动启用业务。
- 后台在微信用户桌面会话中由独立计划任务托管；SSH 命令结束后继续运行，核对仅存在一个 supervisor 和一个后端。
- 在线账号自动进入就绪状态；离线账号独立等待。没有执行人工发送验收、点击恢复或自动生成验收通过记录。

## 数据与回退

- 首次接入保留完整原目录，程序版本与共享 data 分离。管理员、登录会话、角色/API 配置、会话开关和暂停状态与接入前一致。
- 实际执行了一次本机程序回退，随后重新应用同一份 GitHub 构建包；两次检查均通过，始终使用当前数据库，没有用旧备份覆盖业务数据。
- 聊天归档继续增量增长，已有发送记录保留。重复提交、上传中断、连续更新选择最新提交、候选启动失败、切换中断恢复，以及启用后回退保留新数据由自动化测试覆盖。
- 生产验证没有发送测试消息。就绪状态已验证；新版本的自然消息回复闭环以实际到达的合格消息和发送记录为准，不能以健康接口成功替代。

## 接入时修正的问题

- Windows 桌面会话与 SSH 会话隔离：首次接入也由交互式部署任务执行。
- 新目录冷启动等待不足：增加启动余量，独立记录计划任务输出；异常退出可重试，正常停止保持停止。
- 便携 Python 的系统 CA 不完整：使用已锁定依赖中的 CA 证书包，继续验证 TLS。
- Windows 与 Linux 的 SSH 密钥换行及 SFTP 路径差异：规范化换行，使用 `/C:/...` 绝对上传路径；Linux 实际上传验证通过。
- 日志分页与实时刷新并发：等待正在加载的页完成后再刷新；增加确定性的浏览器回归场景，修复前复现失败、修复后连续三次通过。

首次发布与回退验收后开启仓库变量 `AUTO_DEPLOY_ENABLED=true`。本记录的 main 推送用于验证后续自动发布；具体结果以该提交对应的 GitHub Actions 和服务器发布状态为准。
