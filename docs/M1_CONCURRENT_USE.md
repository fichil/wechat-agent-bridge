## 实现

- ConsolePolicy 的读取检查不再因 user_active 拒绝。绑定群读取只比较账号、会话行、标题和输入节点身份，不要求草稿为空，也不比较草稿内容。运行中的原生读取只检查输入桌面是否可访问，不采样全局输入时间、焦点或剪贴板。
- 读取、模型、发送三个独立调度线程；桌面操作仍串行。慢模型请求和不可用发送通道不阻塞同步。每会话最多保留一条已生成待发回复，新触发继续合并进下一项任务；定时记忆继续处理。
- ready 回复与任务一起 DPAPI 加密保存。通道未就绪不 claim、不预留发送额度、不重复调用模型；真正写入前仍先持久化任务和额度。unknown 保留并封锁该会话的后续发送，读取及摘要继续。暂停/撤权取消待发；重启取消 pending/processing/ready/sending，清除待发正文，保持暂停，不集中补发。
- 新增 `POST /api/read-channel`，参数 account、conversation、window、automation_id，仅允许从已有绑定会话接入明确选定的独立群窗口。核验同进程、完整源指纹、精确客户端群根 AutomationId、标题标签及稳定 RuntimeId；不按昵称枚举或猜测窗口。独立窗口中的草稿值不被读取。来源/会话认证及 CSRF 检查沿用原接口。
- `GET /api/status.execution` 返回 read/model/send 状态、生成中及待发数量、各通道能力。页面区分读取/AI 与发送未就绪，不再把历史人工操作事件显示成当前暂停。已绑定的独立聊天窗口从账号发现结果中排除，其他同 PID 窗口不会被一概去掉。
- `IsolatedChannel` 是合成验证的独立发送契约，尚无真实 Windows sender 接入；资格要求双向草稿隔离、光标/选区/输入法、主窗导航、焦点/剪贴板、发送回显、同构建恢复等证据齐全。HTTP 无法设置这些资格。
