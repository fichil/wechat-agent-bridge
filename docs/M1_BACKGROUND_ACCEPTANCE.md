## 已实现的保护和控制台入口

- `--live-acceptance`：固定本机验收数据目录；每次启动暂停，账号与两个会话需在新进程中重新核验，不能从昵称或旧配置自动继承身份。
- `--allow-accessibility-patch`：默认关闭；控制台先绑定所选窗口和预期微信号，再单独启用、检测、恢复。普通启动不会自动写进程字节。
- 开关校验版本、DLL SHA-256、静态指令、模块边界、可写映射、进程创建时间及窗口归属；原值在写入前用 DPAPI 持久化。父进程拥有恢复器，UIA 子进程超时被终止后仍尝试恢复。
- 恢复采用身份和值校验，不向复用 PID 写入；失败保留恢复记录，不隐藏异常。强制终止主进程时不能承诺已经恢复，后续绑定必须处理恢复记录。
- 本轮 API 与发送额度使用独立 SQLite 事务日志；跨重启、配置修改、记忆删除和数据目录选择不重置。发送另有三个不可复用的类别槽位；没有退款或重试 unknown 的入口。
- 合成测试中的验收 Scope 只允许两条已核验会话；私聊初始/恢复基线和历史回填不进入上传上下文，群上下文最多 50 条。**真实客户端尚未具备完整 Scope、稳定消息身份及己方/@ 语义，控制台不会因此开启真实自动运行。**
- 新后台发送事务独立测试了 SetValue、完整回读、再次核对、Invoke 和己方新消息回读的契约；真实端没有获得该契约的支持声明。
- 已把本次抢焦点结果保存为能力阻塞；实际适配器拒绝发送，原草稿实验也拒绝重复执行，需先实现新的后台写入方案并评审证据。
