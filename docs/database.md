# 数据库设计与恢复

## v9 微信兼容暂停

当前版本为 v9。新增 `compatibility_state`，分别保存当前 Windows 用户范围与各账号的构建指纹、修订号、能力快照和持久暂停原因。兼容暂停独立于用户暂停、AI 重试与迁移暂停；启动检查不会自动清除账号暂停。恢复使用修订号检查，取消旧待发送队列、保留 `unknown`、更新 epoch 与实时水位，不重放停用期间消息。

升级前通过 SQLite backup API 写入 `migration-backups/before-v9-<UUID>.sqlite3`，表与版本在同一事务提交。完整迁移包接受合法 v8/v9 数据，在暂存库升级后再替换目标。回退必须同时恢复对应程序和一致数据库备份，并保留回退前数据供核对；不修改微信客户端版本。

## v8 会话频率与群聊处理轮次

v8 中，`conversation_preferences` 增加 `scan_interval_seconds`（默认 2）与 `group_proactive_message_threshold`（默认 0，关闭）。迁移不修改现有 AI 开关、暂停状态、角色/API、记忆、消息或发送记录；旧归档不回填群聊实时计数。

从旧版本升级前，通过 SQLite backup API 保存 `migration-backups/before-v8-<UUID>.sqlite3` 并执行完整性检查。v8 新字段、资格表、轮次表与版本标记在同一事务提交；失败回滚。群聊轮次按固定消息快照分批提交记忆与完成标记，最终回复、触发消费和发送队列原子落库。重启时未完成的模型请求标为中断并暂停；已完成批次不重做，未发起的后续批次保留。

群聊计数资格按启用代次隔离，重复扫描和消息修正不新增资格。等待素材的消息在就绪后才计入可处理条数；关闭后重新开启 AI 不把停用期间消息作为新发言触发。关闭主动调用只取消主动轮次与尚未提交的主动发送，不取消 @ 轮次或已提交的原生发送。

回退需要正常停止服务并保留当前数据库及 WAL/SHM，再恢复一致的旧数据库备份和对应源码；不得仅降低 `user_version`。恢复旧快照会丢失快照之后的新归档和发送记录，应先核对这些差异。

SQLite 位于 `.local/bridge.sqlite3`。数据只存于本机，按当前 Windows 用户访问的账号隔离；公开 ID 为持久化随机 UUID，不使用 PID 作为历史身份。

## 关系和索引

| 表 | 主键、约束与用途 |
| --- | --- |
| accounts | account_id 主键，wxid 唯一；资料、在线状态、最后同步时间、账号 revision |
| conversations | conversation_id 主键，(account_id, source_id) 唯一；摘要、分类、排序、头像引用 |
| messages | message_id 主键，(account_id, conversation_id, identity_key) 唯一；结构化正文、发送者、源引用、sort_key、change_seq |
| sync_state | (account_id, shard, table_name) 主键；generation、baseline_id、last_id、upper_id、signature、started_at |
| history_ranges | (account_id, conversation_id, lower_key, upper_key) 主键；经过完整源读取证明的连续排序区间 |
| media_cache | cache_key 主键；头像/图片的 BLOB、MIME、SHA-256、字节数、质量和最近使用时间 |
| conversation_settings | 稳定账号指纹主键；完整七项布尔设置 JSON |
| role_cards | 全局 `card_code` 主键；名称、完整 V2 JSON、修订号和创建／更新时间 |
| api_profiles | 全局 `profile_id` 主键；服务商、协议、基础地址、模型、DPAPI 密钥密文和修订号 |
| ai_defaults | 单行约束；全账号共用的角色卡/API 外键和独立修订号 |
| conversation_preferences | `(account_id, conversation_id)` 主键；AI 开关、角色卡外键、长文本记忆和独立修订号 |
| group_message_eligibility | message_id 主键；群聊实时资格、启用代次、首次观察时间和已消费任务，重复／修正不重新计数 |
| group_rounds | round_id 主键；固定轮次、触发原因、原始 @ 消息、批次进度，同会话最多一个 active 轮次 |
| group_round_messages | `(round_id, message_id)` 主键；消息顺序、输入快照、内容指纹、素材指纹和处理完成状态 |
| sync_jobs | task_id 主键；状态和小型结果引用，完成任务最多保留 256 个且不超过一天 |
| cursors | 不透明 token 主键；账号/会话/操作绑定、边界和有效期，数量有界 |
| metadata、schema_migrations | 一次性设置迁移标记、来源状态及 schema 版本 |

消息去重优先使用正数 server_id（十进制字符串）。无有效 server_id 时采用来源代次、分片及 local_id，账号和会话始终参与唯一约束。
源文件身份或盐改变、local_id 回退时使来源代次变化，避免把新记录覆盖到旧历史。WAL checkpoint 本身不改变逻辑代次。

`message_order(account_id,conversation_id,sort_key,message_id)` 支持复合游标深分页；`message_changes(account_id,conversation_id,change_seq,message_id)` 支持增量变更；变更流与消息显示顺序分开，避免低排序值迟到消息丢失。

版本 3 新增角色卡和会话配置，不修改已有微信来源资料。角色卡没有账号归属；会话配置通过复合外键验证账号与会话归属，角色卡外键使用 `ON DELETE RESTRICT`，引用索引支持统计和删除检查。会话列表批量读取开关和配置修订号，长文本记忆仅在配置详情接口读取。来源同步刷新 `conversations.payload` 不会触及配置表，归档会话暂不活跃或被过滤时也保留配置和角色引用。

角色修改、删除和会话配置写入在数据库所有者线程使用事务串行执行。客户端提交 `expected_revision`，冲突返回 409，既有数据不变；配置更新只合并显式提交的字段。删除在事务内检查引用数量，不提供级联删除。提交成功后才发送全局角色卡通知或按账号和会话限定的配置通知，不在通知或日志中包含正文。版本 3 迁移失败会回滚新增表、索引和版本号，原库仍可重试迁移。
文本正文、发送者和解析结果以 JSON 保存，排序、来源、编号、代次另有索引列。图片采用 BLOB，不在任务表重复保存 Base64。

## 事务与覆盖语义

数据库由一个专用线程、一个连接拥有；HTTP 查询在线程池等待结果，异步事件循环保持可响应。启用 WAL、FULL 同步、外键、内存临时表及有限页缓存；写入和 checkpoint 在同一连接串行执行。文件锁拒绝第二个后端实例。

每一批消息写入与对应分片水位在同一事务提交，提交后才发布通知。磁盘满、SQL 错误或进程中断不能留下已推进而消息缺失的水位。重试采用 UPSERT，不重复创建稳定消息 ID。

首次只记录每表最高 local_id；之后固定本批 upper_id，按 local_id 排序分批读取，未处理完保留 upper_id。新增会话/分片同样有界处理。联系人、原始会话及分片 Name2Id 联合解析源会话；无法映射时保留明确问题，不猜测归属。

历史覆盖不使用新增水位推断。源历史分页完整成功后才合并 history_ranges；失败分片重试原边界。已缓存的两个区间之间存在缺口时，不宣称完整历史，不静默跨越缺口。`coverage=complete` 表示当前连接到源起点的已读取历史；离线状态和最近同步时间另外披露。

聊天归档保留已经取得的消息，不自动镜像源库删除。变化来源每表复核最近 25 条缓存记录及最多 25 条待转写语音，后者按最后复核时间轮转，不限于最近消息；只保存微信已有转写。更早的其他内容修改需要显式刷新相应范围。迁移版本 2 为待转写语音增加部分索引。

## 容量和故障

默认有效图片缓存为 512 MiB，普通图片、静态表情与 GIF 共用 `kind=image` 的 LRU 配额，不删除文字或头像。数据库删除 BLOB 后会复用空闲页，运行中不执行阻塞性 VACUUM，因此文件大小不等于有效图片容量。任务表保存消息 ID 引用和图片元数据，不另存图片正文。

表情仍保留 `type=sticker` 及原消息 ID，通过已有 `source_ref` 按需定位源消息；旧归档无需迁移或重新导入。成功获取后将原文件作为 BLOB 保存，HTTP/工作进程 JSON 边界使用标准 Base64，GIF 动画字节不变。下载地址、表情加密字段及完整 XML 不写入消息响应、任务表或日志。资源首次未缓存且微信离线时返回 `source_offline`；缓存命中不访问源或网络。

数据库版本不匹配、完整性检查失败、占用或迁移失败均停止写入并报错；不会自动删除、重命名或重建原库。旧设置 JSON 只迁移一次，损坏文件保持原样。

## 备份与恢复

版本 4 增加 `api_profiles`、`ai_defaults` 和会话的 `api_profile_id` 外键。升级在一个事务中完成，失败回滚新增表、列、索引和版本。现有角色卡按 `(created_at, card_code)` 选第一条为默认，不重写原角色文档、会话选择、开关或记忆。空会话引用表示持续继承全局默认；会话查询返回有效配置和来源，数据库不复制默认 ID。

引用统计为显式绑定与“已开启 AI 且通过默认值继承”的会话并集，包含暂不活跃或被过滤会话。在同一写事务中检查引用并删除，外键使用 RESTRICT；未使用默认项删除前先清空默认外键并递增默认修订号。默认切换不递增会话自身修订号；全局通知使客户端重新解析配置。开启 AI 和已开启会话更换绑定时事务内校验依赖；缺失则整次保存失败。旧数据已开启但缺少配置时保留开关并报告不可用，仍允许关闭或单独保存记忆。

API 密钥仅以当前 Windows 用户 DPAPI 密文保存，写入失败不产生部分配置。查询只包含 `has_key` 和 `key_readable`，不返回明文或密文。API 配置更新省略密钥时保留密文，传入新密钥时重新加密；解密失败可以通过替换密钥修复。跨电脑或 Windows 用户恢复数据库后通常需要重新填写密钥。角色卡默认标记不写入 V2 JSON，因此导出格式保持兼容。

归档排除出 Git，不随源码同步到远端。源码备份不等于聊天数据备份。

最简单的备份方式：正常停止此项目后端，确认数据库所有者已退出，再复制数据库及仍存在的同名 WAL/SHM 到用户指定的本地备份目录。不要在服务运行中仅复制主 `.sqlite3` 文件，也不要删除 WAL。需要在线备份时应在数据库所有者线程调用 SQLite backup API；本次未提供自动备份任务。

恢复前正常停止后端，保留当前数据库及 WAL/SHM 的完整副本，再恢复同一备份集合；启动时检查 quick_check 和版本。归档可以离线查询，源微信同步仍需重新确认当前账号。不要用数据库查看工具在服务运行时并发修改归档。

参考：[SQLite WAL](https://www.sqlite.org/wal.html)、[SQLite UPSERT](https://www.sqlite.org/lang_upsert.html)、[SQLite 复合游标](https://www.sqlite.org/rowvalue.html)。


## 版本 5：模型调用与增量记忆

新增 `ai_settings`（全局提示词及修订号）、`api_verifications`（绑定配置修订号的测试结果）、`api_tasks`（不含候选密钥的测试状态）、`ai_sessions`（自动触发、暂停和取消代次）、`ai_runs`、`ai_run_messages` 和 `ai_message_state`。会话增加独立 `memory_revision`。版本 4 到 5 的 DDL、初始化及版本号在同一事务内完成。

`ai_runs` 对账号／会话／请求标识唯一；部分唯一索引保证每个会话只有一个排队或运行任务。网络调用在独立双线程执行器中，绝不占用数据库事务或微信读取队列。同一会话的远程执行还有互斥锁，取消后重新启用也不会并行发送。输入快照只保留执行必需的内存对象；数据库记录消息 ID、内容指纹、所用配置修订号及公开结果，不保存请求中的密钥或重复的 Base64。

成功响应校验后，在单事务中检查记忆修订号和取消代次，再保存记忆、回复、任务状态和消息覆盖标记。自动记忆更新只增加 `memory_revision`；编辑操作继续校验配置修订号，编辑记忆还检查 `expected_memory_revision`。处理标签变化推进消息增量游标，独立于源内容指纹，因此通知不会造成重复调用。

配置测试成功后，配置／密文、验证结果和成功任务状态一起提交，避免重启把已保存的配置误报为未保存。测试期间发生配置修订冲突则拒绝候选配置。重启将未完成任务标为中断并暂停对应会话；已完成任务不重放。模型超时可能发生在服务方已计费之后，因此只提供明确的手动重试，不承诺远端恰好执行一次。

迁移保留所有旧角色卡、API、默认值、消息、记忆和开关；旧 API 的验证状态为未验证。数据库集合及一致性快照仅保存在 `.local`，不得进入源码备份。当前用户 DPAPI 密文跨 Windows 用户通常不可解密。

## 版本 6：独立诊断日志

`diagnostic_logs` 保存账号／会话、任务关联、冻结的配置元数据、开始／最近时间、调用结果与本地应用结果；`diagnostic_details` 单独保存按需读取的脱敏 JSON 和正文字节数，通过日志 ID 级联删除。v5→v6 建表、索引、历史摘要初始化及版本号在同一事务完成。旧任务未保存的快照、请求、原始响应不补造。

日志创建在模型请求发出前，响应在解析前采集，每次降级和图片探测均单独记录。业务完成后附上本地提交、冲突、取消等结果。观察器错误被隔离；日志保存失败不影响原任务。服务重启将残留运行记录标为中断，不触发重发。来源自动检查以账号、操作、范围及标准化内容指纹合并，保留首次时间、最近时间及次数；手动、新内容和错误仍可单独排查。

列表只读取摘要，详情查询同时验证账号范围；全局测试记录无账号归属，扫描全局记录仅含数量摘要。游标绑定账号和筛选条件。查询、写入及启动时清理 7 天前的已结束记录；超过 512 MiB 时依次清理最旧的已结束正文并提示。运行中的 HTTP 或尚未完成本地应用的记录均受保护。SQLite 复用空闲页，因此归档文件大小可能高于当前有效日志正文量。

日志正文按用户要求保留聊天、提示词和记忆，但不保留认证头、Cookie、API 密钥、微信解密材料或图片 Base64。源图片与模型输入图片分别留下 MIME、字节数和 SHA-256 摘要；取首帧标记仍保留。日志和本地数据库备份仅留在 `.local`，不进入浏览器持久存储、WebSocket 正文、控制台或源码备份。


## 版本 7：实时触发与原生发送队列

从 v6 升级前使用 SQLite backup API 创建 `migration-backups/before-v7-<UUID>.sqlite3`，完整性检查成功后才开始迁移。新增表和索引、已开启会话的启用水位及版本号在同一事务提交；失败回滚并保留 v6 原库。现有账号、消息、角色卡、API 密文、记忆及开关不重写；旧运行不创建待发送记录。备份仅留本机。

| 表 | 用途 |
| --- | --- |
| delivery_sessions | 每账号／会话的独立启用时间、同步代次和每表水位，以及 3 秒合并窗口 |
| reply_triggers | 原始消息 ID 唯一，记录触发资格、AI 代次和消费该触发的运行 ID |
| deliveries | `(run_id, part_index)` 唯一；原会话 ID、不可变回复分段、状态、尝试数及两类回执 |
| delivery_attempts | 提交前持久化尝试，保存开始／完成时间及原生结果 |

只有实时增量越过源水位且通过启用时间、方向、消息类型和群提及检查，才能建立触发记录；历史补录不能建立触发。页面提前补录的新消息在实时游标追上后仍能建立资格；若此前已处理记忆或模型正在运行，会保留下一轮回复机会。已消费消息的内容更新不会重新触发。

AI 结果、记忆、触发消费和发送分段在同一事务中提交。发送尝试先从 queued 原子变为 sending 并记录尝试，再调用外部进程；发送失败只重用原段。重启把 sending 及未完成尝试标为 unknown，不自动重发；queued 保留。未知结果暂停同会话后续发送，独立账号不受影响。关闭 AI 取消 queued/failed，不改变已提交操作；重新启用建立新水位和代次，不能复活已取消任务。

归档回读只作为独立佐证：账号、会话、本人方向、文本及发送尝试时间匹配且候选唯一时记录消息 ID，不把回读当作原生回执或自动解除 unknown。模型输入附带最近回复的发送状态；未发出内容不得作为已发送事实。

回退 v6 必须正常停止后端，保留当前库及 WAL/SHM 后，用升级前的一致性备份恢复，并使用 v6 源码。不要直接降低 user_version，也不要在原生任务运行中回退。恢复旧备份会失去升级后的新归档和发送状态，因此先保存完整当前副本，核对所有可能已提交的发送。
