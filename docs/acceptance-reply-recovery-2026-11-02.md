# 自动回复恢复与日志性能修复

## 原因与行为

模型请求返回时，旧逻辑把临时发送暂停等同于关闭 AI，丢弃结果并清除后续调度。现在仅在账号身份、会话代次、角色/API/提示词和记忆修订仍有效时接受结果；文字、图片、表情与记忆在同一事务提交。暂停时不能领取发送任务，恢复后按序处理，成功和未知结果继续沿用原有防重发规则。

初始消息基线完成后，后台历史追赶不会阻塞已有效触发的会话。同步错误、通道忙碌和身份失效分别记录；取消原因区分关闭 AI、处理代次变化、群聊触发失效与配置冲突。

同步诊断在归档完成后批量保存，每批最多 20 项。相同自动读取结果忽略耗时差异合并，保留次数与最新耗时。容量使用覆盖索引，不读取详情正文；过期清理每分钟最多 200 条，容量清理使用余下预算并在后续批次继续，活动任务日志保留。新增索引向后兼容，SQLite 版本仍为 11。

账号和兼容状态读取设置 8 秒超时；断连显示最后成功检查时间，旧账号与能力标为历史状态，恢复成功后重新显示当前状态。诊断详情区分原生读取、数据库排队、归档与日志写入耗时。

## 离线验证

- 回归覆盖模型返回期间临时暂停、恢复、重启、关闭 AI、身份/配置失效、群聊阈值触发，以及混合队列顺序和发送证据。
- `scripts/verify_log_performance.py` 使用独立临时目录：13,000 条、494,143,000 字节的合成详情；覆盖索引容量查询 0.264–0.711 毫秒，容量清理连续批次删除 200、200、50 条，耗时约 15.8、14.8、4.5 毫秒，活动记录保留。数据量及索引、清理规则断言加入发布流水线，时间仅作为本机测量，不作跨机器绝对承诺。
- 首轮后端 336 项、读取器 54 项、前端单元 41 项及 API 类型、生产构建通过。新增恢复测试另行通过；最终提交以流水线完整验证为准。
- 浏览器新增超时、断连、历史就绪状态与恢复测试；更新原有断连提示断言，并让媒体截图滚动适应异步状态刷新。

## 发布与线上验收

通过现有生产流水线部署，保留 `C:\Apps\WeChatAgentBridge`、共享数据库、记忆、素材和发送记录。不批量恢复历史取消任务。发布后核对当前指针与运行进程，持续观察至少 10 分钟，并以新消息触发的自动任务及可关联发送记录验收；健康检查和人工回复不替代自动回复证据。失败时只回退程序，保留最新数据库。真实结果在执行后回报。
